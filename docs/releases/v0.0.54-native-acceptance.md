# v0.0.54 native acceptance — 2026-09-20

Tested a packaged `0.0.54-rc.2` app launched from Finder on macOS 26.5 (Apple M3 Pro). Developer ID signing and `codesign --verify --deep --strict` succeeded after unlocking the Mac. Microphone and Accessibility permissions were granted. CoreAudio recovered without restarting the audio service.

## Defect found and fixed

The first candidate recorded and transcribed the synthetic fixture, but later crashed in `dictation::terminal → capsule::hide_capsule → NSWindow orderOut`. macOS reported “Must only be used from the main thread.” The terminal fallback now dispatches panel hiding to the main thread and rechecks session ownership inside that queued operation. The rebuilt candidate remained running beyond the fallback timer in the successful trials below.

The first delivery attempt was blocked by the destination guard and is not counted as a successful paste. The test harness was then changed to service its run loop during processing and compare preserved clipboard payloads while allowing the app's restoration marker.

## Live results

Synthetic Samantha speech was played through the speakers and captured by the built-in microphone: “The silver bicycle is beside the blue garden gate. Please bring seven yellow notebooks tomorrow.” Recognition used Parakeet TDT v3 with S1 cleanup enabled. These are acceptance trials, not a latency benchmark or a physical-key timing measurement.

| Trigger | Destination | Result | Native stop command to observed insertion |
|---|---|---|---:|
| System Check recording button | TextEdit | Exact insertion once; History `verified`; one new record | 925.23 ms |
| Synthetic Fn hold/release through the native event monitor | TextEdit | Exact insertion once; History `verified`; one new record | 834.23 ms |
| Synthetic Fn hold/release, two subsequent trials | Chrome textarea | History `verified`; native AX independently confirmed exactly two fixture insertions after two trials | 843.05 / 871.70 ms |
| Synthetic Fn hold/release | Zed | Saved test file contains exactly one insertion; History `unverified`, `destination_not_readable` | Not reported |
| Synthetic Fn hold/release, then a new copy after insertion | TextEdit | Exact insertion; newer clipboard text survived the delayed restoration | 733.52 ms |
| Quit during recording, before release | TextEdit | No insertion and no new History record; process exited and clipboard remained intact | Not applicable |

The successful ordinary-delivery trials preserved the controlled plain text, RTF and custom-type clipboard payloads. The app remained running beyond its terminal-hide timer. The newer-copy trial deliberately replaced those payloads and verified that Linty preserved the new copy. The quit trial complements the native pipeline tests for cancellation after recognition; it does not simulate every cancellation timing.

Two earlier Chrome trials had `unverified` outcomes and are excluded from the successful counts. Browser automation did not establish the intended native field focus. Later, the browser tool's DOM/screenshot readouts also failed to reflect native text changes; an independent native AX read matched the test field description and its exact contents: the initial prefix plus two fixture insertions. Those native checks are the Chrome evidence. Zed's saved synthetic file provides independent evidence despite its unreadable AX field.

The initial harness did not restore the clipboard contents that preceded testing; subsequent harness runs restored their pre-run clipboard. No private clipboard contents are included in this report or the evidence. The original signed 0.0.52 bundle was restored, its signature verified, and it was relaunched successfully. Test windows and the local browser server were closed.

The Rust suite passed again after the fix: 115 unit tests plus one logging integration test, with four asset-dependent tests ignored. The production build and signature verification passed. Structured results are in [native acceptance evidence](../benchmarks/native-acceptance-2026-09-20.json).

## Scope and release status

Packaged recording and delivery acceptance passed for the tested TextEdit, Chrome and Zed paths. Native pipeline tests cover logical cancellation, persistence failures and uncertain delivery; the live checks add real permissions, audio capture, native key posting, exact readable-field verification, an unreadable editor, clipboard restoration, new-copy preservation and quit during capture.

There is no exhaustive live stress coverage of focus-change races, sleep/wake, webview reload, alternative keyboard layouts or other applications. The first attempt exercised a destination rejection, but was not a controlled focus-race test. These checks do not establish a general latency improvement. Public signing/notarization and validation of the distributed artifact still belong to the release workflow.
